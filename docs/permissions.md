# macOS 권한 가이드

simpleKvm 클라이언트(Mac)는 두 가지 권한을 씁니다. 둘 다 **사용자가 직접 허용해야 하며, 앱이나 스크립트가 대신 부여할 수 없습니다.** 자동화가 가능한 부분은 재번들 시 앱을 재시작하는 것뿐입니다.

앱 안의 **"권한 및 진단"** 카드에서 현재 상태를 볼 수 있습니다.

---

## 1. 손쉬운 사용 (Accessibility)

**용도:** 받은 입력 이벤트를 CGEvent로 Mac에 주입합니다. 이 권한이 없으면 연결은 되지만 마우스·키보드가 전혀 움직이지 않습니다.

**부여 방법**

1. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용
2. 목록에 `simpleKvm` 추가 후 체크

앱의 "손쉬운 사용 설정 열기" 버튼으로 바로 이동할 수 있습니다.

**자동 확인:** 가능합니다. `AXIsProcessTrusted()`로 정확히 판정하며, 진단 카드에 `허용됨` / `권한 필요`로 표시됩니다.

**재빌드 시 유지되는가:** 이 권한은 바이너리 서명 정체성에 묶입니다. ad-hoc 서명(`codesign -s -`)은 빌드마다 cdhash가 바뀌어 권한이 무효화됩니다. `scripts/create-signing-cert.sh`로 만든 고정 자체 서명 인증서(`simpleKvm Self-Signed`)를 쓰면 재빌드해도 유지됩니다. `bundle-mac.sh`는 이 인증서가 있으면 자동으로 사용하고, 없으면 ad-hoc으로 넘어가며 그 사실을 출력합니다.

---

## 2. 로컬 네트워크 (Local Network)

**용도:** LAN의 Windows 서버로 TCP 연결하고, mDNS로 서버를 자동 발견합니다.

**부여 방법**

1. 시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크
2. `simpleKvm` 토글 켜기

앱의 "로컬 네트워크 설정 열기" 버튼으로 바로 이동할 수 있습니다.

`packaging/macos/Info.plist`의 `NSLocalNetworkUsageDescription` 키가 있어야 권한 요청이 동작합니다. 이 키는 이미 설정되어 있습니다.

**자동 확인: 불가능합니다.**

- 이 권한은 TCC가 아니라 Network Extension 패킷 필터로 강제되며, 상태를 읽는 공개 API가 없습니다.
- 대안으로 "mDNS browse를 돌려 응답이 오는지"로 판정하는 방법을 실측 검증했으나 **신뢰할 수 없어 채택하지 않았습니다.** 동일한 번들을 동일한 권한 상태에서 반복 실행했을 때 결과가 아래처럼 갈렸습니다.

  | 실행 | `_simplekvm` resolve | 메타 쿼리 응답 |
  |---|---|---|
  | 1회차 | 0 | — |
  | 2회차 | — | 9종 |
  | 3회차 | 0 | 3종 |
  | 4회차 | 2 | 9종 |

  서버는 네 시점 모두 광고 중이었습니다(`dns-sd`로 확인). 실패 사례의 원인은 규명되지 않았습니다. 이 지표로 "권한 없음"을 표시하면 오진이 나므로, 진단 카드는 판정 대신 **관측값만** 보여줍니다(발견된 서버 수, 마지막 mDNS 응답 경과 시간).

**직접 확인하는 방법**

```bash
# 서버가 광고 중인지 (OS 레벨, 권한 게이트 영향 없음)
dns-sd -B _simplekvm._tcp local

# 광고된 인스턴스의 호스트/포트
dns-sd -L "<서버이름>" _simplekvm._tcp local

# 호스트의 IPv4 주소
dns-sd -G v4 <호스트>.local
```

`dns-sd`로는 보이는데 앱에서 안 보인다면, 앱이 최신 빌드로 실행 중인지부터 확인하세요(아래).

## 3. 재번들 후 재시작이 필요한 이유

`bundle-mac.sh`는 `dist/simpleKvm.app/Contents/MacOS/kvm-client`를 덮어씁니다. 이미 실행 중인 프로세스는 **원래의 메모리 이미지를 그대로 유지**하므로, 재번들만 하고 앱을 재시작하지 않으면 새 코드가 반영되지 않습니다. 파일은 최신인데 동작은 예전이라 권한 문제처럼 보이기 쉽습니다.

대응은 두 가지입니다.

- `bundle-mac.sh`가 실행 중인 앱을 감지하면 종료 후 다시 실행합니다.
- 진단 카드에 **실행 중인 빌드의 시각과 커밋**을 표시합니다. 프로세스 시작 시점의 실행 파일 mtime을 기록해 두었다가 파일이 더 새것으로 바뀌면 `더 새 빌드가 설치되었습니다. 앱을 재시작해야 반영됩니다.`를 띄웁니다.

수동 확인:

```bash
# 실행 중인 프로세스 시작 시각
ps -o lstart= -p "$(pgrep -f dist/simpleKvm.app/Contents/MacOS/kvm-client)"

# 번들 바이너리가 기록된 시각
stat -f "%Sm" dist/simpleKvm.app/Contents/MacOS/kvm-client
```

프로세스 시작 시각이 바이너리 기록 시각보다 **이르면** 구 이미지가 실행 중입니다.

## 4. 참고

- 로컬 네트워크 권한은 실행 파일 UUID를 식별에 사용합니다(Apple TN3179). 등록 상태는 `/Library/Preferences/com.apple.networkextension.uuidcache.plist`에서 볼 수 있습니다. 단, **이 파일의 항목이 비어 있다고 해서 권한이 없다는 뜻은 아닙니다** — 항목이 빈 번들이 정상적으로 mDNS를 수신하는 것을 실측으로 확인했습니다.
- macOS에는 로컬 네트워크 권한을 "미결정" 상태로 되돌리는 공식 방법이 없습니다.
